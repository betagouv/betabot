# Incubator activity report (`create-report.ts`)

Generates a weekly markdown activity report for one beta.gouv.fr incubator.

```sh
npx tsx create-report.ts <incubator-slug> [--since=YYYY-MM-DD] [--until=YYYY-MM-DD]
# or
npm run create-report -- mtes
```

`<incubator-slug>` must be a key of `data/API/incubators.json` (e.g. `mtes`, `dinum`, `menj`). On a miss, the script prints the full list of valid slugs and exits 1.

Defaults to the last 7 days ending today. `--since`/`--until` override the range for ad-hoc reports.

Output: `data/reports/{slug}/{since}_{until}.md` (gitignored, like the rest of `data/`).

## Repos ensured at startup

The script clones (if missing) or `git pull`s two repos before building the report, so it's self-sufficient even if `get-data.sh` hasn't run recently:

- `data/beta.gouv.fr` — `github.com/betagouv/beta.gouv.fr`, `--depth=500`. Also cloned by `get-data.sh` (see `specs/data.md`).
- `data/doc.incubateur.net` — `github.com/betagouv/doc.incubateur.net-communaute`, `--depth=500`. Already cloned by `get-data.sh`; pulled again here for freshness.

## Report sections

### Startups

- **New startups**: a startup is "new" if `content/_startups/{id}.md` was **added** (git `--diff-filter=A`) within `[since, until]` in `data/beta.gouv.fr` — not derived from `phases[].start` in the API, since a startup's file can be created with historical phase dates already set (e.g. an `investigation` phase from months earlier). Listed with pitch and a link to `https://beta.gouv.fr/startups/{id}`.
- **Startup content changes**: for every *other* startup in the incubator (new startups are excluded here — their only "diff" is the file creation itself, already covered above), `git log --since --until -- content/_startups/{id}.md` against `data/beta.gouv.fr`. If commits exist in range, the full diff between the oldest and newest commit in the window is fed to the LLM (`summarizeStartupDiff`, capped at `MAX_DIFF_CHARS` = 8000 chars) to produce a 1–3 sentence French summary of what changed. That summary and a link to `https://github.com/betagouv/beta.gouv.fr/commits/master/content/_startups/{id}.md` are shown in the report — the raw diff itself is not included in the output. Any URL added or removed in the diff (`extractChangedUrls`, matched on `+`/`-` lines only, so unchanged context lines are ignored) is always listed explicitly under **URLs modifiées**, since the LLM summary can paraphrase a link away instead of quoting it.

### Membres

A member is "new" for the incubator if any of their `missions[]` (from `data/API/members.json`) has a `start` date in `[since, until]` **and** that mission's `startups[]` field intersects the incubator's startup ids. This uses the per-mission `startups` field for exact join dates — it does **not** use the SQLite `members.created_at` column (that's each member's *first-ever* mission across the whole community, not scoped to this incubator).

Each new member is listed with name (linked to `https://espace-membre.beta.gouv.fr/community/{id}`), role, the startup(s) they joined, bio, and any `link`/`github` fields.

### Documentation beta

`git log --since --until --name-only` against `data/doc.incubateur.net` (`getDocChanges`), with **no incubator-relevance filtering** — every doc commit in the range is included, since the repo isn't organized per-incubator and keyword filtering was dropping/hiding relevant changes. For each commit, `git show {hash} --format=` fetches the actual patch (capped at `MAX_DOC_DIFF_CHARS` = 1500 chars/commit, to keep the total facts blob bounded once every commit in range is concatenated). The commit list (date, files, **diff — not the commit subject**) is sent to the LLM (`summarizeDocChanges`) **numbered but without links or commit messages**, and the model is asked to group changes by topic (`### Theme` headings) with one `- N: summary` bullet per change, referencing the change by its number and basing the summary strictly on the diff content. The script then rebuilds each bullet's link itself from the referenced `DocChange`, rather than trusting the model to reproduce a full commit URL verbatim — long literal strings like a 40-char SHA embedded in a URL aren't always copied correctly by the model, which would otherwise produce a silently broken link. Any line that doesn't match the expected `- N: ...` format, or references a number outside the given list, is dropped rather than rendered.

### Intro paragraph

A short French summary generated by a single one-shot call to the existing OpenAI-compatible client (`config.openai.*`, same client setup as `src/orchestrator.ts`), fed a compact facts block (counts + names, including each startup diff's LLM summary) rather than the full diffs/bios. Prioritizes new startups/members and the most impactful changes over minor ones. Tone is neutral and factual — no promotional/motivating language.

## Known limitations

- Startup diffs only cover changes within `[since, until]`; a startup edited just before `since` and again just after `until` won't show the full picture, only what changed inside the window.
- The "new member" and "new startup" detection both key off the boundaries of `[since, until]` inclusively on the `start` date string — dates are compared as `YYYY-MM-DD` strings, so no timezone conversion is applied.
- The doc-changes section covers the whole `doc.incubateur.net` repo, not just changes related to this incubator — for an incubator with a quiet month, it can be the longest section in the report.

## Suggested follow-ups

- No automated test/eval exists for this script since it's I/O-heavy (live git clones + LLM call). Worth a manual spot-check after changes: run against a known incubator/date range and diff the output against `git log` run directly.
